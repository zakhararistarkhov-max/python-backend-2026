# ДЗ 5: покрытие тестами и CI

[Условие](../lecture5/hw/README.md) ·
[GitHub Actions](https://github.com/zakhararistarkhov-max/python-backend-2026/actions/workflows/hw5-ci.yml)

Решение продолжает ветку `hw4`: тестируется весь пакет `hw2/hw/shop_api`,
включая REST API из ДЗ 2, WebSocket-чат, SQL-хранилище и метрики.
Лекции, сами тесты и сторонние библиотеки не входят в измеряемый пакет.
Внутри `shop_api` нет исключений из покрытия.

## Запуск

Из корня репозитория (Python 3.13 или 3.14):

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r hw2/hw/requirements.txt
cd hw2/hw
python -m pytest --cov --cov-config=.coveragerc \
  --cov-report=term-missing --cov-report=xml --cov-report=html -v
```

Без `DATABASE_URL` тесты создают временную SQLite-базу и удаляют её после
запуска. Локальный результат на Python 3.14: **144 passed, 15 skipped**,
**99,56%** совокупного покрытия строк и ветвлений (381/382 строк и 75/76 ветвей).
Единственный непокрытый путь — создание PostgreSQL engine.

С реальной PostgreSQL 17 локально на Python 3.14 прошли **все 159 тестов**:
**100% строк и ветвлений** (382/382 строк и 76/76 ветвей).

Порог **95%** задан в [`.coveragerc`](../hw2/hw/.coveragerc).
Если покрытие ниже порога, команда завершается с ошибкой.
HTML-отчёт находится в `hw2/hw/htmlcov/index.html`, XML — в
`hw2/hw/coverage.xml`; сгенерированные отчёты не коммитятся.

## Проверяемые сценарии

| Область | Проверки |
| --- | --- |
| REST API | CRUD, валидация, отсутствие ресурсов, пагинация, фильтры, мягкое удаление, переполнение цены |
| SQL-хранилище | Ограничения и внешние ключи, откат транзакций, сохранение данных, конкурентное добавление товаров |
| WebSocket | Изоляция комнат, формат сообщений, отключение клиентов, бинарные сообщения, ошибки чтения |
| Жизненный цикл | Создание схемы при старте, освобождение engine при остановке, сохранение записей при повторном старте |
| Метрики и конфигурация | Счётчики и гистограммы, запрет произвольных меток, параметры SQLite, неподдерживаемый SQL-диалект |

Новые проверки находятся в `test_lifecycle.py`. Фикстура клиента в
`test_shop_extra.py` использует контекстный менеджер `TestClient`, чтобы
WebSocket-соединения работали в одном цикле событий, а lifespan выполнялся
при запуске и завершении теста.

## CI с PostgreSQL

Workflow [HW5 Coverage](../.github/workflows/hw5-ci.yml) запускается на push,
pull request и вручную. Матрица включает Python 3.13 и 3.14:

- **SQLite:** весь набор тестов, 15 PostgreSQL-тестов пропускаются.
- **PostgreSQL 17:** отдельный service container с healthcheck;
  `DATABASE_URL` переключает исходные API-тесты на PostgreSQL,
  `TEST_POSTGRES_URL` включает 15 интеграционных тестов в изолированных схемах.
  Дополнительные SQLite-проверки также выполняются.

Для каждой из четырёх jobs независимо проверяется порог 95% и загружаются
HTML/XML-отчёты в Actions Artifacts. Тесты PostgreSQL проверяют реальные
транзакции, блокировки, ограничения, конкурентные обновления и HTTP-контракт.

Для такого же запуска локально укажите обе переменные перед командой pytest
из раздела выше:

```sh
export DATABASE_URL='postgresql+psycopg://shop:shop@localhost:5432/shop_test'
export TEST_POSTGRES_URL="$DATABASE_URL"
```

Используйте отдельную пустую тестовую БД: исходные API-тесты создают в ней
товары и корзины. Интеграционные тесты создают и удаляют собственные схемы;
пользователю БД нужны права на создание схем.
